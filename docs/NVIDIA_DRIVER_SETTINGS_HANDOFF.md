# 게임마다 켜기: PC 확인 안내

이 문서는 ‘게임마다 켜기’ 화면이 실제 NVIDIA 드라이버에서 의도대로 동작하는지 PC에서 확인하는
순서입니다. 저장소의 테스트는 메모리 안의 가짜 드라이버 설정과 NVAPI 대역으로만 돌기 때문에,
실제 `nvapi64.dll` 호출은 이 확인으로 처음 증명됩니다. 드라이버 설정을 바꾸는 일이라 펌웨어나
메인보드와는 관계가 없고, 언제든 화면의 되돌리기로 앱이 바꾸기 전 값으로 돌릴 수 있습니다.
확인하는 동안 NVIDIA 앱과 NVIDIA 제어판은 닫아 둡니다. 드라이버 설정은 동시에 저장한 내용을 합치지
않아서, 앱과 같은 순간에 저장하면 한쪽 내용이 사라집니다.

## 준비

- GitHub Releases에서 최신 릴리스를 받습니다. 아직 릴리스에 들어가지 않은 변경을 확인할 때는 그 변경이 병합된 `master` 커밋의 사전 배포판(pre-release)을 받습니다.
- 드라이버 616.64(또는 그 이후)인 PC에서 앱을 **관리자 권한으로** 실행합니다.
- 비교용으로 NVIDIA 앱이나 NVIDIA Profile Inspector를 열어 둘 수 있으면 좋습니다. 앱은 이 둘에
  기대지 않고, 값을 맞게 썼는지 눈으로 대조하는 데만 씁니다.

## 확인 순서

1. **목록 읽기:** 홈에서 ‘게임마다 켜기’를 엽니다. ‘드라이버 616.64에 등록된 게임 N개’가 나오는지,
   N이 수천 개인지, 화면이 뜰 때까지 몇 초 걸리는지 적어 둡니다.
2. **NVIDIA가 켜 둔 게임:** 검색에 `cyberpunk`(또는 NVIDIA가 Resizable BAR를 켜 둔 다른 게임)를
   입력합니다. 스위치가 켜져 있고 설명이 ‘NVIDIA 기본값’인지 봅니다.
3. **한 게임 켜기:** 꺼져 있는 게임 하나를 켭니다. 스위치가 잠시 돌다가 켜진 채 남는지,
   ‘이 PC에서 바꾼 게임’에 그 게임이 나오는지 확인합니다. ‘되돌리기와 진단 기록’을 펼쳐
   ‘이 PC에서 바꾼 프로필 1개’와 전체 사본 경로가 보이는지도 확인합니다
   (`%LOCALAPPDATA%\io.github.nvstrapsrebar.desktop\nvidia-driver-settings\`).
4. **값 대조:** NVIDIA Profile Inspector에서 같은 게임 프로필을 열어 아래 값이 들어갔는지 봅니다.
   NVIDIA 앱을 쓴다면 그 게임의 Resizable BAR가 ‘켜기’로 나오는지 봅니다.

   | 설정 | 기대값 |
   | --- | --- |
   | `0x000BFA21` (NVIDIA 앱 Resizable BAR, Profile Inspector에서는 rBAR - Enable v2) | `0x00000002` |
   | `0x000F00BA` rBAR - Enable | `0x00000001` |
   | `0x000F00BB` rBAR - Options | 프로필에 원래 값이 없었다면 `0x00000001` |
   | `0x000F00FF` rBAR - Size Limit | 프로필에 원래 값이 없었다면 `0x0000000040000000` (1 GiB) |

5. **게임에서 확인:** 그 게임을 실행해 평소처럼 동작하는지 봅니다. 이미 켜져 있던 게임은 다시
   실행해야 바뀐 값을 읽습니다.
6. **다시 끄기:** 같은 게임을 끕니다. 원래 꺼져 있던 게임이면 Profile Inspector에서 위 값들이
   사라지고(기본값으로 돌아가고), 화면 설명에서 ‘이 PC에서 바꿈’이 빠지는지 봅니다.
7. **NVIDIA가 켜 둔 게임 끄기:** 2번의 게임을 끕니다. Profile Inspector에서 `0x000BFA21`이
   `0x00000000`, rBAR - Enable이 `0x00000000`으로 들어갔는지 봅니다. 확인 뒤 다시 켜거나 9번으로
   되돌립니다.
8. **모든 게임:** ‘모든 게임’ 스위치를 켭니다. 동의 창이 뜨는지, ‘모두 켜기’를 누른 뒤 아무
   게임이나 검색했을 때 설명이 ‘‘모든 게임’ 설정’으로 켜져 보이는지 확인합니다. Profile
   Inspector의 `_GLOBAL_DRIVER_PROFILE (Base Profile)`에 4번 표의 값이 들어갔는지 봅니다. 확인했으면
   다시 끕니다(끌 때는 창이 뜨지 않습니다).
9. **되돌리기:** ‘되돌리기와 진단 기록’에서 ‘바꾸기 전 값으로 되돌리기’를 누르고 확인합니다.
   3~8번에서 바꾼 프로필의 값이 모두 처음 상태로 돌아가는지 Profile Inspector로 봅니다. 2번의
   게임은 설명이 다시 ‘NVIDIA 기본값’이어야 하고, Profile Inspector에서도 rBAR - Enable이 NVIDIA
   값으로 보여야 합니다. 그 사이 NVIDIA 앱 등에서 바꾼 다른 설정은 그대로 남아야 합니다.
10. **관리자 권한 없이:** 앱을 일반 권한으로 열어 이 화면에 들어갑니다. 목록이 읽히는지,
    ‘관리자 권한으로 다시 여세요’ 카드와 함께 스위치가 잠기는지 봅니다. 목록 읽기부터 실패하면 그
    문구를 적어 둡니다.

## 진단 기록

앱은 드라이버 설정 명령을 실행할 때마다 아래 파일에 한 줄씩 남깁니다. 결과를 알려 주실 때 이
파일을 함께 보내 주시면 됩니다. 화면의 ‘되돌리기와 진단 기록’을 펼치면 같은 경로가 보이고, 오류
안내에도 이 경로가 붙습니다.

- `%LOCALAPPDATA%\io.github.nvstrapsrebar.desktop\logs\driver-settings.log`: 명령의 시작과 끝,
  걸린 시간, 실패한 NVAPI 호출과 그 인자, 쓴 값과 지운 값, 바꾸기 전 값과 다시 읽은 값(설정마다
  값, 위치, NVIDIA 기본값 여부), 읽지 못해 목록에서 뺀 프로필, 건너뛴 백업과 그 이유. 2 MiB를
  넘으면 `.log.1`로 넘기고 새로 씁니다.
- `%LOCALAPPDATA%\io.github.nvstrapsrebar.desktop\logs\panic.log`: 앱이 예기치 않게 꺼졌을 때의
  위치와 메시지. 배포판은 패닉 시 바로 종료하므로 이 파일이 유일한 흔적입니다.

## 알려 주실 결과

단계마다 된 것과 안 된 것을 적어 주시면 됩니다. 특히 다음 네 가지가 다음 수정에 필요합니다.

- 1번의 게임 수와 걸린 시간.
- 4번과 7번에서 Profile Inspector나 NVIDIA 앱에 보인 실제 값.
- 화면에 뜬 오류 문구(아래 줄의 영어 원문까지)와 그때 누른 스위치.
- 616.64에서 `0x000BFA21`만 바꿔도 NVIDIA 앱 표시가 바뀌는지, 기존 rBAR 값과 함께 바꿔야 하는지에
  대한 관찰.
- 진단 기록의 `drs.accessors` 줄. 설정을 읽고 쓰는 함수로 드라이버 자체 함수가 잡혔는지 공개
  함수가 잡혔는지 보여 줍니다.

## 문제가 생기면

- 화면의 ‘바꾸기 전 값으로 되돌리기’가 앱이 바꾼 프로필의 값만 처음 상태로 돌립니다.
- 앱이 열리지 않는다면 NVIDIA Profile Inspector에서 해당 게임 프로필의 위 네 값을 되돌립니다.
  `nvidia-driver-settings\originals.json`에 프로필마다 바꾸기 전 값이 남아 있고, `nvidia`에 적힌
  설정은 NVIDIA가 값을 정해 둔 것입니다. 이런 설정은 지우지 말고 Profile Inspector에서 설정 하나를
  기본값으로 되돌리는 기능을 씁니다. 지우면 NVIDIA 값까지 사라지고, 드라이버의 되돌리기 함수로도
  다시 살릴 수 없습니다(아래 확인 결과). 이미 지웠다면 앱이 첫 변경 전에 남긴 전체 사본을 불러와야
  하며, 그 전에 사본과 지금 설정을 비교해 다른 변경이 사라지지 않는지 봅니다.

## 이 확인으로 증명되는 것과 남는 것

- 증명: NVAPI 함수 번호와 구조체 크기가 실제 드라이버와 맞는지, 관리자 권한이 필요한지, 드라이버가
  쓴 값을 다시 돌려주는지, 드라이버 자체 설정 함수가 잡히는지, 되돌리기가 실제로 동작하는지.
- 남는 것: 게임 안에서 Resizable BAR가 실제로 쓰였는지는 드라이버가 보고하지 않습니다. 체감
  성능이나 다른 도구로 판단합니다.

## PC 확인 결과 (2026-10-03)

RTX 2080 SUPER, 드라이버 616.64에서 저장소의 무시된 테스트
(`src-tauri/src/nvidia_profiles/on_pc.rs`)로 1~4번과 6~10번을 돌렸습니다. 화면을 누르는 대신 화면이
부르는 명령 코드(`load_catalog`, `change`, `undo`)를 실제 `nvapi64.dll`에 연결해 실행했고, 백업과
되돌리기 기록과 진단 기록은 앱과 같은 `%LOCALAPPDATA%\io.github.nvstrapsrebar.desktop` 아래에
남겼습니다. 값은 Profile Inspector 대신 쓰기와 무관한 새 드라이버 세션에서 다시 읽어 대조했습니다.

- 1번: 게임 7,799개, 읽지 못한 프로필 0개, 0.37초(릴리스 빌드). 관리자 권한 없이도 읽힙니다.
- `drs.accessors`: 읽기, 쓰기, 지우기, 되돌리기 모두 드라이버 자체 함수(`0xEA99498D`,
  `0x8A2CF5F5`, `0xD20D29DF`, `0x7DD5B261`)가 잡혔습니다.
- 2번: Cyberpunk 2077은 rBAR - Enable이 NVIDIA 값 1로 켜져 있었고 NVIDIA가 켜 둔 게임은 58개였습니다.
- 3~4번: 꺼져 있던 게임(RF Online Next)을 켜면 표의 네 값이 그대로 들어갑니다.
- 6번: 다시 끄면 네 값이 모두 사라지고 ‘이 PC에서 바꿈’도 빠집니다.
- 7번: NVIDIA가 켜 둔 게임(Arc Raiders)을 끄면 `0x000BFA21`과 rBAR - Enable이 0으로 들어갑니다.
  다시 켰다가 끄는 경우에도 같습니다. 켤 때 써 넣은 rBAR - Enable 1은 NVIDIA 값과 같아서 드라이버가
  NVIDIA 값으로 표시합니다.
- 8번: ‘모든 게임’을 켜면 Base Profile에 네 값이 들어가고, 꺼져 있던 게임은 ‘‘모든 게임’ 설정’으로
  켜진 것으로 읽힙니다. 끄면 네 값이 모두 사라집니다.
- 9번: 되돌리기 뒤 세 프로필의 네 값이 처음과 같습니다. Arc Raiders는 NVIDIA 값으로 돌아왔습니다.
- 10번: 관리자 권한이 없어도 목록은 읽힙니다. 쓰기를 막는 화면 카드와 잠긴 스위치는 이번에 보지
  않았습니다.

첫 실행에서 결함이 하나 나왔습니다. 드라이버의 지우기 함수는 NVIDIA가 정해 둔 값까지 지우는데, 앱은
되돌리기에서 그 함수를 썼습니다. 그래서 Cyberpunk 2077을 끄고 되돌리자 rBAR - Enable이 NVIDIA 값 1이
아니라 ‘값 없음’이 되었고, NVIDIA가 켜 둔 게임이 57개로 줄었습니다. 그 뒤에는 설정 하나를 되돌리는
함수(`RestoreProfileDefaultSetting`)도 네 값 모두에 `NVAPI_SETTING_NOT_FOUND`(-160)를 돌려주어 다시
살릴 수 없었습니다. 이제 앱은 NVIDIA 값이 있는 설정을 지우지 않고 그 함수로 되돌리며, 되돌리기 기록에
그런 설정을 적어 두고 되돌린 뒤 NVIDIA 값이 다시 쓰이는지 확인합니다. 고친 코드로 7번과 9번을 다시
돌려 Arc Raiders가 NVIDIA 값으로 돌아오는 것을 확인했습니다.

이 PC의 Cyberpunk 2077은 프로필 전체를 되돌리는 함수(`RestoreProfileDefault`)로도 살아나지 않았습니다.
함수는 성공을 돌려주었지만 rBAR - Enable은 여전히 ‘값 없음’이었습니다. 지운 NVIDIA 값을 되살리는 길은
앱이 첫 변경 전에 남긴 전체 사본(`backups\*.nvdrs`)을 불러오는 것뿐입니다. 사본과 지금 설정을
프로필마다 비교하는 무시된 테스트(`the_installed_driver_compares_the_backup`)를 돌리면 7,968개
프로필 가운데 Cyberpunk 2077의 rBAR - Enable 하나만 다르고, 이 PC에서 쓴 다른 값은 모두 같습니다.
관리자 권한으로 `NVSTRAPS_LOAD_BACKUP=1`을 주면 같은 드라이버 버전이고 다른 차이가 없을 때만 사본을
불러오고, 불러온 뒤 다시 비교합니다.
이 PC에서 그렇게 사본을 불러온 뒤 다시 비교하니 차이가 0개였고, Cyberpunk 2077은 다시 NVIDIA 값으로
켜져 NVIDIA가 켜 둔 게임이 58개로 돌아왔습니다.

남은 확인은 5번(게임 실행), NVIDIA 앱 화면에 보이는 값(`0x000BFA21`만으로 표시가 바뀌는지), 그리고
10번의 화면 표시입니다.
## 확인 결과 갱신 (2026-10-09)

유지 관리자가 같은 PC에서 게임마다 켜기 스위치를 실제 게임으로 확인했습니다. 화면에서 켠 게임을
다시 실행하면 Resizable BAR가 적용되므로, 위에 남겨 두었던 5번(게임 실행)은 끝났습니다. 이 화면은
이제 설계대로 동작하는 기능이고, 이 문서는 다른 PC에서 같은 확인을 되풀이할 때의 순서로 남습니다.

이 확인을 저장소의 CI로 옮길 수는 없습니다. GitHub가 제공하는 Windows 러너에는 NVIDIA GPU도
NVIDIA 드라이버도 없어 `nvapi64.dll`을 부를 수 없고, 드라이버가 없는 곳에서 게임을 실행해도 증명되는
것이 없습니다. CI는 메모리 안의 가짜 드라이버 설정으로 정책과 되돌리기 규칙을 검사하고, Playwright로
화면 여정을 검사합니다. 실제 드라이버에 쓰는 확인은 앞으로도 NVIDIA 드라이버가 있는 PC에서 무시된
테스트(`src-tauri/src/nvidia_profiles/on_pc.rs`)나 이 문서의 순서로 합니다.
